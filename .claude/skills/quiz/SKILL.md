# 每日日文練習出題

規則來源：`AGENTS.md`（分類、格式、build、deploy）與 `CLAUDE.md`「Practice session style」（題目語言與兩條 track）。本檔只寫流程，不重抄規則；衝突時以那兩份為準。

## 0. 參數與模式

- 用法：`/quiz [科目] [題數]`，例：`/quiz 文法 10`、`/quiz 文字`、`/quiz 模試`。沒指定科目就是「綜合」，預設 8 題；沒指定就直接開考，不要先問。
- 科目對照 JLPT（N2 計分：言語知識〔文字・語彙・文法〕／読解／聴解 各 60 分，每科都有基準點）：

| 科目 | 參數 | 出的大題 | 預設題數 |
| --- | --- | --- | --- |
| 文字 | `文字`・`もじ` | 漢字読み（漢字→讀音）・表記（假名→漢字） | 10 |
| 語彙 | `語彙`・`ごい` | 語形成（接頭・接尾語）・文脈規定（填詞）・言い換え類義・用法（四個句子挑用法正確的） | 10 |
| 文法 | `文法`・`ぶんぽう` | 文法形式の判断（填文型）・文の組み立て（★ 排序）・文章の文法（短文裡的空格） | 10 |
| 読解 | `読解`・`どっかい` | 內容理解（短文 200–300 字・中文 400–500 字）・主張理解・情報檢索（告示、表格） | 3 篇 |
| 聴解 | `聴解`・`聴` | 不在這裡出，改叫 `listen` skill | — |
| 模試 | `模試` | 文字 → 語彙 → 文法 → 読解 依序各出幾題，像正式考試的順序 | 20 |
| 綜合 | （不指定） | 下面「1. 選題來源」的錯題複習＋非日檢題型 | 8 |

- 現階段是 N2 考前衝刺，難度以〔N2〕為主，可混少量〔N3〕基礎題與〔N1〕。Miyago 自評基礎弱、會靠漢字直覺讀題，所以文字・語彙題的干擾選項要專抓這點：字形或字義相近的漢字、促音・長音・濁音・拗音、音讀訓讀混淆。
- **拿掉漢字拐杖**：Miyago 能靠中文漢字字義與音讀猜中大部分題目，這不代表真的會。文字・語彙題至少一半要做成「看不到漢字也得會」的形式：
  - 漢字読み 優先出**訓讀**與和語（例：{潔|いさぎよ}い、{専|もっぱ}ら、{賄|まかな}う、{和|なご}む），音讀題只出有例外讀音的字。
  - 表記題的干擾選項要用中文字義也說得通的漢字（例：【はかる】→ 図る／計る／測る／量る），不能光靠字義刪去。
  - 語彙題（文脈規定・言い換え類義・用法）的題幹和選項整句**全假名、不放漢字**，逼他靠聲音和語感認字。
- 大題的名稱與形式參考 JLPT 官方公開的題型；題目一律自編，不抄官方或市售考古題。
- 開始前先 `git pull --ff-only`，因為 Mac 和 Windows 兩台都會寫入 vault。

## 1. 選題來源與比例

- 綜合模式：約一半是 `vault/mistakes/my-pitfalls.md` 既有錯題的同類變化題（同文法點、換詞或換語境），其餘從 `vault/minna/*.md` 未勾選 `- [ ]` 的文型、`vault/basics/grammar/*.md`、`vault/compare/*.md`、近期 `vault/examples/` 的文法點抽。
- 科目模式：文法題優先從 vault 已有的文型與錯題出；文字・語彙題可以出 vault 外的 N2 常見詞，但答錯的詞要記進 `vault/basics/vocab/` 對應單字本（依 AGENTS.md）。
- 偏重最近內容：用 `git log --since="2 weeks ago" --name-only` 或檔案修改時間挑檔，不要整個 vault 全讀。
- 每題開頭標來源檔（相對路徑）；vault 外的題寫「來源：N2 常見詞」。

## 2. 題型與標記

- 日檢題型（科目模式與模試）：一律**四選一**，用 `AskUserQuestion` 工具出題，讓 Miyago 直接點選，不要叫他打數字。
  - 一次呼叫只放一題（`questions` 只放一個），`multiSelect: false`，`header` 寫大題名（例：`漢字読み`，12 字內）。
  - `question` 要自足：題幹整句寫進去（對話框打開時，前面的訊息可能看不到）。
  - 四個 `options` 照日檢順序，`label` 寫 `1 はってん` 這種「號碼＋選項本身」；`description` 留空或只放必要補充，不能洩漏答案或暗示對錯。
  - 用法題（四個句子挑用法正確的）句子太長放不進 label 時，label 寫 `1`〜`4`，句子放 `description`。
  - 読解題：文章先在訊息裡印出來，`question` 再寫「依上面文章：」＋提問；文章短（200 字內）就直接放進 `question`。
  - 對話框會自動多一個「Other」：Miyago 選 Other 打字（例：「不會」「跳過」「提示」）時照他說的處理，不算作答。例外見下一條。
  - 排序題照日檢格式：四個空格中一個標 ★，問 ★ 位置填哪個，選項一樣用 `AskUserQuestion`。
- **不確定標記**：Miyago 在 Other 打「號碼＋猜的／不確定」（例：「2 猜的」「3 不確定」）時，視為選了該號選項，並標記為不確定。不確定的題不論對錯，都要給完整詳解並記錄（見 §4）。
- 對話裡（含 `AskUserQuestion`、批改的詳解）不渲染 ruby，`{漢字|かな}` 一律不要用：讀音寫成 `漢字（かな）`，例：出（で）ないと。文字題（漢字読み・表記）不附讀音。ruby 只用在寫進 vault 的檔案。
- 綜合模式另外輪替非日檢題型，不連續兩題同型：中→日 翻譯、日→中 拆解、活用填空（例：`食べる → たら形`）。
- 每題標 **JLPT track** 或 **日常 track**（依 CLAUDE.md），並標難度〔N5〕〜〔N1〕與大題名（例：「文法｜文法形式の判断〔N2〕」）。
- 日文只出現在題目與例句，說明、提示、批改一律繁體中文。

### 解析格式

#### 短解析（答對、且沒標不確定）

- 只給兩行：第一行「對，正解是幾號」；第二行一句重點，說正解為什麼對（規則、字義，或文法題的接續，例：`動詞辞書形 ＋ わけにはいかない`），必要時順帶點出最容易掉進的陷阱。
- 不列選項表、不附專課連結；詳細內容留給完整詳解（答錯時才會給）。

#### 完整詳解（答錯、或標了不確定，不論對錯）

1. 判定：答錯寫「錯」，答對但標不確定寫「猜對」；寫出 Miyago 選的號與正解號。
2. 題目整句（對話裡不用 ruby）。
3. **每個選項一列**，四個都要列（含正解），欄位固定：

| 選項 | 意思 | 接續 | 典型短例句（附中文） | 為什麼放不進這題 |
| --- | --- | --- | --- | --- |

- 文字・語彙題沒有接續的話，「接續」欄改寫讀音或字形要點。
- 正解那一列的「為什麼放不進這題」寫「正解」與它成立的理由。

- **判斷線索**：題幹裡哪個字詞決定答案，一兩句。
- **記憶點**：一句，附 vault 專課連結（先 Glob 確認路徑）。
- 読解題另外標出答案根據在文章哪一句。

## 3. 流程（一次一題）

1. 每次只出一題，列出題目後停下，等 Miyago 作答。不要一次把整組題丟出去。日檢題型用 AskUserQuestion 出題，答案回來後直接批改。
2. 批改後分兩路：
   - **答對，且沒標不確定**：給短解析（見解析格式 · 短解析），**同一回合直接出下一題**（呼叫 `AskUserQuestion`）。
   - **答錯，或標了不確定**：
     1. 先依 §4 把完整詳解寫進當日詳解頁（逐題寫，不等收尾）。
     2. 在對話給完整詳解（解析格式 · 完整詳解）。
     3. **結束本回合，不呼叫 `AskUserQuestion`**。最後一行請他回「下一題」，或直接追問。
     4. 他回覆後才出下一題。
     原因：手機上對話框打開時看不到前一則訊息，詳解會被蓋住，所以答錯時不能接著開下一題的對話框。
3. 特殊輸入（Other 打字）：
   - 「提示」（作答前）：給一個不洩漏答案的線索，不算作答，照常等他答。
   - 「詳解」：只在批改後有效，把剛才那題展開成完整詳解，只在對話展開、不改檔；展開後結束本回合，等他回「下一題」。作答前打「詳解」一律當「提示」處理。
4. 全部結束後給總結：對幾題、弱點類別（依文法點或題型歸類），以及建議下次的重點。模試模式另外按科目分列對題數（文字／語彙／文法／読解）。

## 4. 記錄錯題

- **寫入時機**：答錯、或標了不確定的題，批改後、給詳解前，立即寫進當日詳解頁，逐題寫，不等到收尾。
- **當日詳解頁**：`vault/mistakes/quiz/YYYY-MM-DD.md`（當天日期）。
  - 頁面不存在就建立，frontmatter 為 `title / aliases / tags / level / type`：`title: 測驗詳解 YYYY-MM-DD`、`type: mistakes`、`tags: [mistakes, quiz]`、`level` 列本日出現的級別（去重，例：`level: [N2, N3]`）。
  - 頁面第一次建立時，同一輪要做兩件事：在 `.vitepress/config.ts` 的 我的錯題 下註冊「測驗詳解」子群組（最新在前）；把該頁加進 `.github/workflows/deploy.yml` 的 verify 清單。
  - 每題一段，標題格式：`## 第N題｜科目｜大題〔N?〕`。猜對的題在標題尾加 `｜猜對`。N 是本次 session 的題號（從 1 起算）。
  - 段落內容依「完整詳解」：題目（ruby 寫法，例：{出|で}ないと）、選了、正解、四個選項的表格、判斷線索、記憶點、專課連結。表格儲存格裡的 ruby 用 `\|`。
  - 猜對的題只寫進當日詳解頁，不寫進 `my-pitfalls.md`。
  - 專課連結從 `quiz/` 資料夾出發：同分類用 `../basics/...`、`../compare/...`，錯題頁用 `../my-pitfalls.md`。
- **錯題一行**：答錯的題，依 `AGENTS.md`「Vault 分類與自動筆記規則」寫進 `vault/mistakes/my-pitfalls.md`。
  - 每筆在開頭標科目與大題（例：「文字｜漢字読み」），方便之後按科目回顧。
  - 每筆格式：`原句 ✗ → 正確 ✓ → 錯因 → 連到專課`，附難度標記〔N?〕。
  - 行尾加詳解連結：`（詳解：[第N題](quiz/YYYY-MM-DD.md)）`。連到檔案，不加段落錨點（VitePress 與 Obsidian 的 slug 規則不同）。
- 若錯在 `vault/minna/` 某文型：保持該項未勾（`- [ ]`），並在對應專課補一條說明。
- 全對的 minna 文型**不要自動勾**。收尾時問 Miyago 要不要勾，等他回答後才改。
- 日文正確性由 Miyago 確認；寫入時不要自己宣稱「已驗證」。

## 5. 收尾

每 5 題同步一次，讓 Miyago 手機上能在網站看到當日詳解頁；結束時再同步一次。

1. **中途同步**：每批改完第 5、10、15… 題（以作答題數計，答對也算）、寫入 §4 之後，在出下一題或結束回合之前做：
   1. 跑 `bun run docs:build`，必須通過。失敗就停下回報，不 commit。
   2. 只 `git add` 本次實際改動的檔案（當日詳解頁、`vault/mistakes/my-pitfalls.md`、首次建立時的 `.vitepress/config.ts`／`.github/workflows/deploy.yml`、必要時的 minna／專課檔）。不要 `git add -A`，因為工作區可能有其他 agent 的未提交變更。
   3. commit，然後 `git push origin main`。沒有新改動就跳過。
2. **結束同步**：全部題目結束後，做同樣的 build → add → commit → push。
3. commit 訊息：`feat(vault): quiz YYYY-MM-DD 錯題收錄`（日期用當天），中途與結束都用同一格式。不加任何 AI attribution。
4. 推送後回報 commit hash。
5. 日文內容交回 Miyago 確認（假名、活用、furigana、語感）。

## 隱私

- 任何考試成績（總分、分項）都不准寫進 repo 內的檔案；repo 是公開的，網站也是。

## 備註

- 從手機透過 Remote Control 開的 session 也適用。session 跑在桌機上，寫入 vault 是即時的，不需要另外同步。
