# 每日日文練習出題

規則來源：`AGENTS.md`（分類、格式、build、deploy）與 `CLAUDE.md`「Practice session style」（題目語言與兩條 track）。本檔只寫流程，不重抄規則；衝突時以那兩份為準。

## 0. 參數與模式

- 用法：`/quiz [科目] [題數]`，例：`/quiz 文法 10`、`/quiz 文字`、`/quiz 模試`。沒指定科目就是「綜合」，預設 8 題；沒指定就直接開考，不要先問。
- 科目對照 JLPT（N2 計分：言語知識〔文字・語彙・文法〕／読解／聴解 各 60 分，每科都有基準點）：

| 科目 | 參數 | 出的大題 | 預設題數 |
| --- | --- | --- | --- |
| 文字 | `文字`・`もじ` | 漢字読み（漢字→讀音）・表記（假名→漢字） | 10 |
| 語彙 | `語彙`・`ごい` | 語形成（接頭・接尾語）・文脈規定（填詞）・言い換え類義・用法（四個句子挑用法正確的） | 10 |
| 文法 | `文法`・`ぶんぽう` | 文法形式の判断（填文型）・文の組み立て（★ 排序）・文章の文法（短文裡的空格） | 10 |
| 読解 | `読解`・`どっかい` | 內容理解（短文 200–300 字・中文 400–500 字）・主張理解・情報檢索（告示、表格） | 3 篇 |
| 聴解 | `聴解`・`聴` | 不在這裡出，改叫 `listen` skill | — |
| 模試 | `模試` | 文字 → 語彙 → 文法 → 読解 依序各出幾題，像正式考試的順序 | 20 |
| 綜合 | （不指定） | 下面「1. 選題來源」的錯題複習＋非日檢題型 | 8 |

- 現階段是 N2 考前衝刺，難度以〔N2〕為主，可混少量〔N3〕基礎題與〔N1〕。Miyago 自評基礎弱、會靠漢字直覺讀題，所以文字・語彙題的干擾選項要專抓這點：字形或字義相近的漢字、促音・長音・濁音・拗音、音讀訓讀混淆。
- 大題的名稱與形式參考 JLPT 官方公開的題型；題目一律自編，不抄官方或市售考古題。
- 開始前先 `git pull --ff-only`，因為 Mac 和 Windows 兩台都會寫入 vault。

## 1. 選題來源與比例

- 綜合模式：約一半是 `vault/mistakes/my-pitfalls.md` 既有錯題的同類變化題（同文法點、換詞或換語境），其餘從 `vault/minna/*.md` 未勾選 `- [ ]` 的文型、`vault/basics/grammar/*.md`、`vault/compare/*.md`、近期 `vault/examples/` 的文法點抽。
- 科目模式：文法題優先從 vault 已有的文型與錯題出；文字・語彙題可以出 vault 外的 N2 常見詞，但答錯的詞要記進 `vault/basics/vocab/` 對應單字本（依 AGENTS.md）。
- 偏重最近內容：用 `git log --since="2 weeks ago" --name-only` 或檔案修改時間挑檔，不要整個 vault 全讀。
- 每題開頭標來源檔（相對路徑）；vault 外的題寫「來源：N2 常見詞」。

## 2. 題型與標記

- 日檢題型（科目模式與模試）：一律**四選一**，用 `AskUserQuestion` 工具出題，讓 Miyago 直接點選，不要叫他打數字。
  - 一次呼叫只放一題（`questions` 只放一個），`multiSelect: false`，`header` 寫大題名（例：`漢字読み`，12 字內）。
  - `question` 要自足：題幹整句寫進去（對話框打開時，前面的訊息可能看不到）。
  - 四個 `options` 照日檢順序，`label` 寫 `1 はってん` 這種「號碼＋選項本身」；`description` 留空或只放必要補充，不能洩漏答案或暗示對錯。
  - 用法題（四個句子挑用法正確的）句子太長放不進 label 時，label 寫 `1`〜`4`，句子放 `description`。
  - 読解題：文章先在訊息裡印出來，`question` 再寫「依上面文章：」＋提問；文章短（200 字內）就直接放進 `question`。
  - 對話框會自動多一個「Other」：Miyago 選 Other 打字（例：「不會」「跳過」「提示」）時照他說的處理，不算作答。
  - 排序題照日檢格式：四個空格中一個標 ★，問 ★ 位置填哪個，選項一樣用 `AskUserQuestion`。
- 文字題（漢字読み・表記）不加 ruby；其他題目照常用 ruby。
- 綜合模式另外輪替非日檢題型，不連續兩題同型：中→日 翻譯、日→中 拆解、活用填空（例：`食べる → たら形`）。
- 每題標 **JLPT track** 或 **日常 track**（依 CLAUDE.md），並標難度〔N5〕〜〔N1〕與大題名（例：「文法｜文法形式の判断〔N2〕」）。
- 日文只出現在題目與例句，說明、提示、批改一律繁體中文。

### 解析格式（每題批改都要有）

1. 對／錯，正解是幾號。
2. 正解為什麼對：規則或字義，一兩句；文法題附接續（例：`動詞辞書形 ＋ わけにはいかない`）。
3. 每個錯誤選項為什麼錯：一個選項一行，點出陷阱類型（字形近、讀音近、意思近但語感不同、接續不對）。
4. 一句帶走的記憶點，並連到 vault 專課（先 Glob 確認路徑；沒有專課就照 AGENTS.md 補一條）。
5. 読解題另外標出答案根據在文章哪一句。

## 3. 流程（一次一題）

1. 每次只出一題，列出題目後停下，等 Miyago 作答。不要一次把整組題丟出去。日檢題型用 AskUserQuestion 出題，答案回來後直接批改。
2. 批改：
   - 依上面「解析格式」寫解析。
3. 批改完再出下一題。
4. 全部結束後給總結：對幾題、弱點類別（依文法點或題型歸類），以及建議下次的重點。模試模式另外按科目分列對題數（文字／語彙／文法／読解）。

## 4. 記錄錯題

- 答錯的題，或翻譯／造句錯的題，依 `AGENTS.md`「Vault 分類與自動筆記規則」寫進 `vault/mistakes/my-pitfalls.md`。
- 每筆在開頭標科目與大題（例：「文字｜漢字読み」），方便之後按科目回顧。
- 每筆格式：`原句 ✗ → 正確 ✓ → 錯因 → 連到專課`，附難度標記〔N?〕。
- 若錯在 `vault/minna/` 某文型：保持該項未勾（`- [ ]`），並在對應專課補一條說明。
- 全對的 minna 文型**不要自動勾**。收尾時問 Miyago 要不要勾，等他回答後才改。
- 日文正確性由 Miyago 確認；寫入時不要自己宣稱「已驗證」。

## 5. 收尾

1. 跑 `bun run docs:build`，必須通過。失敗就停下回報，不 commit。
2. 只 `git add` 本次實際改動的檔案（`vault/mistakes/my-pitfalls.md`、必要時的 minna／專課檔）。不要 `git add -A`，因為工作區可能有其他 agent 的未提交變更。
3. commit 訊息：`feat(vault): quiz YYYY-MM-DD 錯題收錄`（日期用當天）。不加任何 AI attribution。
4. `git push origin main`，推送後回報 commit hash。
5. 日文內容交回 Miyago 確認（假名、活用、furigana、語感）。

## 隱私

- 任何考試成績（總分、分項）都不准寫進 repo 內的檔案；repo 是公開的，網站也是。

## 備註
